Task 1.4 · Large, infrequent search

S3 Vectors fits big, rare searches

WorkloadStore
Large corpus, a few queries each day or each week, seconds or minutes of latency allowedS3 Vectors. No always-on cluster.
Interactive search with steady, high query volumeAn always-on store such as OpenSearch Serverless. Inference: this fits better than S3 Vectors.

An always-on cluster costs money even when few queries arrive. S3 Vectors removes that cost.

Exam trap: The cheapest store is wrong when the latency need is strict. Check the tolerance first.
