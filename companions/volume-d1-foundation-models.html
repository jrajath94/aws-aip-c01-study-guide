Unit 2 · Topic 1

Foundation models on Bedrock

From the lesson Topic 1

A foundation model is a large model with pre-training on broad data. A team calls the model through an API. The team does not train the model. Inference is one model run on one input. The context window caps the text per request. The window counts tokens.

Amazon Bedrock is the managed front door. One service gives access to models from many providers. One IAM model controls access. One CloudTrail trail records calls. Temperature, top-p, and max tokens shape the next token pick. Temperature 0 gives a fixed pick. That pick suits classification and extraction.

One trap recurs. An AccessDenied error often means model access was never requested for that model in that region. The error does not prove a bad IAM policy.

1 doorone Bedrock door to many model providers
Nugget 2 · One front door From the lesson Topic 1
The lesson

Bedrock gives one door to many models, with one access model and one audit trail.

Why it matters. Per-vendor APIs split access rules and split audit records. One door keeps both in one place.

Transfer. Route a family of models through one control point. Access and audit stay simple.

Unit 3 · Topic 2

Choosing the right model

From the lesson Topic 2

Model choice trades five axes. The axes are capability, cost per token, latency, context window size, and region availability. A golden dataset tests the trade. The dataset is a fixed set of question and answer pairs.

The filter order matters. First apply a capability floor on the golden dataset. Next check region availability. Then rank by cost and latency. Last check the context window. The cheapest model that meets every limit wins.

The trap is a default flagship model for all work. Small models match flagship quality on classification, extraction, and simple summaries. A cascade routes easy work to a cheap model. The cascade sends hard work to the flagship.

Unit4

Unit 4 · Topic 3

3. Calling models: InvokeModel vs Converse vs streaming

From the lesson Topic 3

InvokeModel is the first Bedrock runtime API. Each provider sets a request body shape and a response body shape. InvokeModel is the only API for embeddings. Converse is the newer unified API. Converse uses one request shape across providers. Converse adds tool use, guardrails, prompt caching, and structured output.

ConverseStream returns tokens as the model produces tokens. A chat screen feels fast when tokens start to arrive in 300 milliseconds. The full answer may take 10 seconds. Batch inference is the async option on S3. Batch work takes hours. Batch work costs about half the on-demand price.

ApplyGuardrail is a standalone API. The API applies guardrail filters to any text. The text may come from a model outside Bedrock.

1 APIInvokeModel alone serves embedding calls
Nugget 3 · Embeddings take InvokeModel From the lesson Topic 3
The lesson

Converse cannot produce embeddings at any setting. Embeddings take InvokeModel.

Why it matters. A team that builds all calls on Converse hits a wall at the first embedding job. The wall costs a rebuild.

Transfer. Check the one call a unified API cannot make. Design around that call first.

Unit 5 · Topic 4

4. Inference routing and pricing: profiles, routers, throughput

From the lesson Topic 4

Three tools solve three problems. Cross-region inference profiles solve availability across regions. A profile call uses a prefix such as us., eu., apac., or global. Prompt routers solve cost against quality per prompt. Provisioned Throughput solves a guarantee on capacity.

Provisioned Throughput sells reserved capacity per model unit per hour. Terms run from 1 month to 6 months. Prompt caching bills a repeated input prefix at a lower rate. On-demand billing charges per token with no commitment. On-demand suits spiky traffic and test traffic.

One bug recurs in exam items. A team buys Provisioned Throughput and calls the base model ID. Traffic hits on-demand quotas and throttles. The fix is the provisioned model ARN in the call. More units do not fix a route error. A sound design pairs reserved capacity for a steady base load with on-demand capacity for spikes.

Unit 6 · Topic 5

5. The approach ladder: prompt, RAG, agents, fine-tuning

From the lesson Topic 5

The approach ladder orders four methods by cost. Prompt work comes first. Retrieval-Augmented Generation, or RAG, comes second. Agents come third. Fine-tuning comes last. The rule is strict. Start at the lowest step that can work. Climb only with proof that the lower step fails.

Each scenario verb maps to one rung. Format or tone points to prompt work. Facts or citations point to RAG. Actions or tools point to agents. Baked-in behavior at scale points to fine-tuning.

Fine-tuning on company documents is a classic wrong answer. Trained facts go stale between training cycles. Trained facts cannot cite a source. Documents that update often point to RAG. Answers that must cite sources point to RAG.

4 stepsprompt, RAG, agents, fine-tuning, in cost order
Nugget 4 · The ladder rule From the lesson Topic 5
The lesson

The correct answer is the lowest ladder step that meets all limits.

Why it matters. Each higher step adds cost, delay, and upkeep. A higher step with no proof of need wastes all three.

Transfer. Prove the cheap method fails before you fund the dear method. Keep the proof on record.

Unit8

Unit 8 · Topic 7

7. Custom models: fine-tuning, continued pre-training, distillation, imports

From the lesson Topic 7

Supervised fine-tuning trains a model on labeled prompt and response pairs. The model learns a behavior such as tone or classification. Continued pre-training trains on unlabeled domain text such as manuals. The model absorbs domain words. Distillation trains a small student model to copy a large teacher model on one narrow task.

LoRA trains small weight deltas called adapters. LoRA leaves most weights fixed. Imported models come from work outside Bedrock. Bedrock validates an imported model and serves the model through Bedrock APIs.

Two traps recur. Fine-tuning fits behavior, not facts. A custom model job may succeed and still refuse calls. Most custom models need Provisioned Throughput before a call works. Distillation fits one narrow task at very high volume where cost is the problem.

2 homesfacts in RAG, behavior in weights
Nugget 5 · Behavior, not facts From the lesson Topic 7
The lesson

Fine-tuning bakes in behavior. RAG supplies facts.

Why it matters. A team that trains facts into weights gets stale facts with no citation. The error shows up months later.

Transfer. Put facts in a store you can update. Put behavior in weights you can retrain.

Unit 9 · Topic 8

Swapping models without redeploys

From the lesson Topic 8

AppConfig holds a model choice as runtime configuration. A change takes effect in seconds. No code deploy takes place. Lambda holds the route logic and calls Converse. API Gateway is the stable front door. The three parts form the standard trio for a model swap with no redeploy.

A CloudFormation parameter fails the no-redeploy test. A parameter change redeploys the stack. EventBridge fails the test as well. EventBridge routes events and holds no configuration.

A circuit breaker adds safe failure. The breaker trips after repeat failures. Traffic moves to a fallback model or a cached response. The breaker probes the main model before a return to normal route. The system gets simpler under failure. The system does not die.

Unit 10 · Topic 9

9. Data pipelines for FMs: validation, processing, extraction

From the lesson Topic 9

Bedrock Data Automation processes documents, images, video, and audio into structured output. A standard output mode needs no design work. A custom blueprint mode fits a fixed form. Validation checks data for completeness and sanity before a model or a knowledge base reads the data.

AWS Glue Data Quality runs data quality rules on pipeline output. Amazon Transcribe converts audio to text. Transcribe supports speaker labels and custom word lists. Amazon Comprehend extracts entities, detects language, and detects personal data in text.

Two traps recur. Guardrails filter for safety and do not extract content. Amazon Kendra is enterprise search, not a knowledge base. Answers with citations need Knowledge Bases. A sound chain uses Data Automation for extraction, Lambda for validation, and Glue Data Quality plus CloudWatch for monitor work.

3 jobsextract, validate, monitor, one service each
Nugget 6 · One service per job From the lesson Topic 9
The lesson

Extraction, validation, and monitor work are three jobs. The exam gives each job to a distinct service.

Why it matters. A service picked for the wrong job fails in a quiet way. The pipeline runs and the output stays poor.

Unit 11 · Topic 10

Chunking strategies

From the lesson Topic 10

Chunk work splits a document into pieces for retrieval. Each piece becomes one vector. Fixed-size chunk work splits text every N tokens with an overlap share. The method is cheap and suits uniform text such as FAQ pages. Overlap keeps the end of one piece at the start of the next piece. Boundary sentences stay whole.

Hierarchical chunk work matches on small child pieces. The model receives the large parent piece for context. Semantic chunk work cuts where sense changes. Semantic cuts give the best quality at the highest ingestion cost.

The worked case in the lesson uses 500-token chunks. A 20 percent overlap gives 400 new tokens per chunk. A 2,000-token parent needs 5 chunks. A 40 percent overlap needs about 7 chunks. A chunk change needs a new data source and a full re-ingestion. No quick fix exists.

5 to 7chunks per 2,000-token parent as overlap rises
Nugget 7 · Overlap is a token bill From the lesson Topic 10
The lesson

At 500-token chunks, a move from 20 percent overlap to 40 percent overlap moves a 2,000-token parent from 5 chunks to about 7 chunks.

Why it matters. More chunks mean more vectors, more storage, and more input tokens per answer. Quality gains pay a token price.

Transfer. Price a quality fix in tokens before you adopt the fix. The bill repeats on every query.

Unit 12 · Topic 11

11. Embeddings: Titan Embeddings and Cohere Embed

From the lesson Topic 11

An embedding is a list of numbers for a piece of text. Similar senses sit close in the vector space. Cosine similarity reads the angle between two vectors. A small angle means a close sense match.

Titan Text Embeddings v2 is the low-cost default. The model offers dimensions of 1024, 512, or 256. Cohere Embed has strength in many languages. Cohere uses an input_type value to mark a query or a document. A wrong input_type value lowers match quality.

A dimension cut from 1024 to 256 cuts vector storage to one quarter. Search runs faster. A team measures the accuracy cost on a golden dataset. An embedding model swap needs a full re-embedding of all stored text. Old vectors and new vectors live in distinct spaces. A mix of both spaces breaks retrieval.

Unit13

Unit 13 · Topic 12

Vector stores compared

From the lesson Topic 12

A vector store holds embeddings and finds near vectors fast. The lesson compares the AWS options on cost, scale, and operations work. Amazon OpenSearch Serverless is the managed default for large AWS-native search. Aurora PostgreSQL with pgvector keeps vectors beside relational data. One query can join a customer filter with a similarity search. S3 Vectors is the low-cost S3-native store with no cluster work. S3 Vectors suits prototypes and small workloads. Amazon Neptune is a graph database for multi-hop relation traversal in GraphRAG.

The exam test is a match test. Store traits must match scenario limits. ElastiCache is a cache, not durable vector storage. DynamoDB is not a vector similarity engine. Neptune fits plain document search in no case. Neptune fits only a scenario with relations or multi-hop traversal, such as fraud rings.

Unit14

Unit 14 · Topic 13

13. Knowledge Bases: the managed RAG service

From the lesson Topic 13

Knowledge Bases is the managed RAG service in Bedrock. The service ingests source documents from S3 and other sources. The service chunks text, embeds text, and stores vectors. A sync job keeps the store current as source files change.

Two APIs serve answers. Retrieve returns ranked chunks for custom answer work. RetrieveAndGenerate returns chunks plus a model answer with citations. The citations point to source chunks.

Data source setup fixes key choices at creation. Chunk strategy is one such choice. Embedding model is one such choice. A change to either choice needs a new data source and a fresh sync.

Unit15

Unit 15 · Topic 14

RAG end to end

From the lesson Topic 14

RAG runs in two phases. The ingestion phase loads documents, splits documents into chunks, embeds chunks, and stores vectors. The query phase embeds the question, finds near chunks, and passes chunks plus the question to the model. The model writes an answer from the chunks.

Each phase fails in a distinct way. Ingestion faults give stale or split facts. Query faults give weak matches or a weak prompt. A debug session names the phase first. The fix follows the phase.

RAG fits facts that change and answers that need citations. RAG does not teach tone or format. Prompt work or fine-tuning fits those goals.

2 phasesingestion and query, each with a distinct fault set
Nugget 8 · Name the phase first From the lesson Topic 14
The lesson

A RAG fault lives in ingestion or in query work. The phase names the fix.

Why it matters. A model swap cannot repair a split chunk. A chunk fix cannot repair a weak prompt.

Transfer. Split a pipeline at phase lines before you debug. Test one phase at a time.

Unit 16 · Topic 15

15. Retrieval quality: hybrid search, rerank, query handling, debugging

From the lesson Topic 15

Dense search matches sense. Lexical search matches exact words. Hybrid search runs both and merges ranks. Hybrid search fits text with codes, names, and part numbers.

A reranker reads the top results again with a stronger model. The reranker reorders results by true fit. A rerank step beats a larger top-k in most weak-result cases. Query rewrite fixes a vague or compound question before search.

The debug order in the lesson is fixed. Test retrieval alone with known questions. Check chunk content. Check the embedding model match. Check the prompt last. Most RAG faults sit in retrieval, not in the answer model.

Unit17

Unit 17 · Topic 16

16. Prompt Management, Prompt Flows, and prompt governance

From the lesson Topic 16

Prompt Management stores prompts as versioned assets in Bedrock. A version pins a prompt for a release. Prompt Flows chain prompts, model calls, and logic in a visual flow. A flow suits a fixed multi-step task.

Governance rules treat a prompt as code. A prompt change gets a review. A prompt change gets a test on a golden dataset. A prompt change ships as a new version. A rollback uses the prior version.

A hard-coded prompt in app code fails the governance test. The prompt hides from review and from version control.

Unit 18 · Topic 17

17. Data privacy and compliance in Bedrock

From the lesson Topic 17

Bedrock does not train base models on customer prompts or outputs. Prompts and outputs stay in the customer account boundary. VPC endpoints keep Bedrock traffic off the public internet. KMS keys encrypt data at rest where a service supports customer keys.

Model invocation logs hold prompt and output text. A team controls log access with care. Logs aid debug work and audit work. Logs also hold the most sensitive text in the system.

Region choice is a compliance choice. Data stays in the region a team selects, subject to the inference route in use. A cross-region profile moves inference across regions by design. A residency limit may bar that route.

1 storethe log store holds the most sensitive text
Nugget 9 · Logs hold the sensitive text From the lesson Topic 17
The lesson

Invocation logs aid debug work, and logs hold the most sensitive text in the system.

Why it matters. Open log access spreads prompt text far past the app team. A breach review starts with log access.

Transfer. Guard the log store as you guard the data store. The content risk is equal.

Model Evaluation Basics

From the lesson Topic 18

Bedrock model evaluation scores candidate models on a dataset. Automatic jobs use fixed metrics. Human jobs use reviewer ratings. A golden dataset gives a stable base for both job types.

A team evaluates before a model swap and after a prompt change. Scores on the same dataset make the two runs comparable. A score with no fixed dataset proves little.

Evaluation closes the domain loop. Selection in Topic 2 uses evaluation. Retrieval debug in Topic 15 uses evaluation. Governance in Topic 16 uses evaluation.
