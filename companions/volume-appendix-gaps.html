    Ingestion gaps: AppFlow and Transfer Family

    Two managed services move data into AWS, and one line splits them. Amazon AppFlow is a fully managed integration service that moves data between SaaS applications and AWS services, in both directions, with no custom connectors.

    Mechanism

    From the lesson§1 · Amazon AppFlow

    Two managed services move data into AWS, and one line splits them. Amazon AppFlow is a fully managed integration service that moves data between SaaS applications and AWS services, in both directions, with no custom connectors. GenAI apps need enterprise data that lives in SaaS tools: support tickets, cases, employee records. Hand scripts break when a vendor changes pagination or rate limits, and AppFlow replaces that glue with a managed flow. A flow runs four steps. A connector profile authenticates once to the SaaS app, and AppFlow stores the credentials in Secrets Manager, never in the flow. A flow definition names source, destination, field maps, optional transforms such as mask, truncate, and join, and filters. A trigger runs the flow on demand, on a schedule, or on a SaaS event, with syncs as fast as near real time. Incremental pulls take records changed since the last run, not full snapshots. Common destinations are S3, Redshift, and Salesforce itself.

    From the lesson§1 · AWS Transfer Family

    AWS Transfer Family is the file-drop door. Where AppFlow speaks SaaS APIs, Transfer Family gives managed file transfer endpoints for partners and systems that deliver files, with S3 as the landing zone. The ladder line from the placement chapter is the discriminator: data that arrives as file drops points to Transfer Family, and data that lives in a SaaS app points to AppFlow.

Credentials live in Secrets Manager, never in the flow. Why it matters. Incremental pulls are the cost line: a full snapshot per run pays for the same records again and again. Transfer.     Three services sit at the end of the GenAI pipeline: analytics over graph and vector data, dashboards over all data, and no-code apps for people outside the engineering team.

    Mechanism

    From the lesson§2 · Amazon QuickSight

    Three services sit at the end of the GenAI pipeline: analytics over graph and vector data, dashboards over all data, and no-code apps for people outside the engineering team. Amazon QuickSight is a serverless business-intelligence service with interactive dashboards, paginated reports, and embedded analytics, and no servers to manage. Its in-memory engine, SPICE, imports data and answers dashboard queries from memory. A direct query reads the source per click: slower, and fresh. The SPICE path trades freshness for speed. QuickSight turns S3, Athena, Redshift, and RDS data into shareable dashboards, with row-level security so each viewer sees only their rows, and ML insights for anomaly flags and forecasts. GenAI systems make data worth a dashboard: token spend per team, evaluation scores over time, retrieval hit rates, user feedback.

    From the lesson§2 · Neptune Analytics and Q Apps

    Neptune Analytics covers the graph and vector analytics corner of the pipeline: questions about links between entities and about vector sets, in one analytics home. Amazon Q Apps covers the no-code end: business users build small apps from Q Business with no code, for tasks that never justify an engineering ticket. The exam frame for the trio is placement: dashboards go to QuickSight, graph and vector analysis goes to Neptune Analytics, and a no-code app ask goes to Q Apps.

    Security and inference primitives

    The guards sit around the app and the dials sit inside the model calls, and AWS tests each entry here as a one-line discriminator.

    Mechanism

    From the lesson§3 · AWS Secrets Manager

    The guards sit around the app and the dials sit inside the model calls, and AWS tests each entry here as a one-line discriminator. AWS Secrets Manager stores secrets: database passwords, API keys, OAuth tokens. KMS encrypts the secrets, and automatic rotation is the headline feature. Rotation swaps a secret on a schedule with no human action and no break for apps that read the secret. Staged rotation solves the break risk: the new value proves itself while the old value still works, then the new value turns current. Apps read secrets at runtime via the API and never embed them. A rotation interval can sit at 30 days, and AWS ships rotation functions for RDS, Redshift, DocumentDB, Neptune, and MongoDB Atlas. Other systems take a custom Lambda.

    Illustration§3 · Rotation step-through

    Open the four rotation steps in order.

    Step 1 · createSecret

    The rotation Lambda makes the new value and stages it as AWSPENDING. The current value stays live.

    Step 2 · setSecret

    The new value goes onto the target database or service.

    Step 3 · testSecret

    The new credential must prove it works. A fail at any step leaves the old secret current, and no app breaks.

    Step 4 · finishSecret

    The staged value turns AWSCURRENT. Apps that read at runtime pick the new secret up with no deploy.

    4 steps createSecret, setSecret, testSecret, finishSecret in Secrets Manager Nugget 3 · From the lesson §3 · AWS Secrets Manager The lesson Rotation runs four steps in order: createSecret, setSecret, testSecret, finishSecret. A fail at any step keeps the old secret current. Why it matters. Hardcoded credentials leak and hand-rotated passwords stall. The staged swap is the whole point: proof before promotion. Transfer. Stage, prove, promote. Any credential swap with no proof step is an outage plan. UNIT 06 · AIP-C01

    From the lesson§3 · AWS WAF and Amazon CloudFront

    AWS WAF is the web firewall at the edge of the app: it filters hostile web traffic before the traffic reaches your endpoints. Amazon CloudFront is the content delivery network in front of the app: it caches and serves content from edge locations close to users. Both sit in the safety column of the ladder map, ahead of the application. The discriminator is the ask: attack filter means WAF, fast global delivery means CloudFront.

    From the lesson§3 · The CountTokens API

    The CountTokens API counts tokens before the call. Send the same request body you plan to send to the model, and the service returns the count. Compare the count with the model context window. An input that does not fit gets a shrink before the real call, not a failure after it. This is the proactive half of token safety: count first, call second.

    From the lesson§3 · top_k, the parameter Converse hides

    top_k limits sampling to the k most likely next tokens. The trap is placement. Converse inferenceConfig holds maxTokens, stopSequences, temperature, and topP, and no topK field. Provider fields such as topK go in additionalModelRequestFields or in a raw InvokeModel body. Bedrock Agents InferenceConfiguration does hold topK. A Converse call with a topK entry inside inferenceConfig is a purpose-built exam trap about where fields live.

Why it matters. Field placement is a top source of ValidationException defects. The parameter is real, and the home in the request decides if the call runs. Transfer. Learn APIs as field maps, not as feature lists. A right feature at a wrong address is a failed call. UNIT 06 · AIP-C01

    From the lesson§3 · CloudWatch Evidently

    CloudWatch Evidently does experiment and feature-flag work inside CloudWatch. Feature flags turn features on or off for a slice of users with no redeploy. Experiments split traffic between variants and measure the winner on a chosen metric, with statistics built in. Prompt Management variants cover prompt text only. Real GenAI experiments change models, retrieval depth, temperature, or whole pipelines, and those need traffic split plus statistics. Two APIs run the loop: EvaluateFeature assigns a variant per user at request time, and PutProjectEvents reports the outcome metric, such as a thumbs-up or a task success. Gradual rollouts use the flag path with no experiment.

    From the lesson§3 · TTFT, time to first token

    TTFT is the time from request send to the first response token. It is the pause a user feels in a stream chat, the wait before text starts. Two kin metrics complete the set: TPOT, the time per output token in the steady stream phase, and end-to-end latency, TTFT plus all that follows. Stream output improves perceived latency, because the first token lands early even when the total run stays the same.

Why it matters. An experiment with no outcome report is a coin flip with extra steps. The report call is what turns traffic split into evidence. Transfer.     Mechanism

    From the lesson§4 · Amazon Textract

    This chapter goes under the pipeline: documents into text, text into chunks, vectors into smaller vectors, models onto endpoints. Amazon Textract is a managed document-analysis service that pulls printed text, handwriting, form key-value pairs, tables, and layout structure from documents and images, with no model to train. Plain OCR gives a word mix. Textract gives structure: table cells, key-value links, checkboxes. That structure lets a chunk pipeline keep a table whole. The API has three types. Synchronous APIs take single-page documents for an instant reply: DetectDocumentText for raw OCR, AnalyzeDocument for structure, with feature types for tables, forms, queries, layout, and signatures. Asynchronous APIs take multi-page PDFs and TIFFs in S3 and return a job ID, with an SNS notice at completion. Specialized APIs cover expenses and ID documents. Low-confidence results go to Amazon A2I for human checks. The trap line: text in a photo is Rekognition work, not Textract work.

    From the lesson§4 · Divider strings for chunking

    Divider strings mark the split points that respect document structure. Boundary-aware splits keep tables and procedures whole: the pipeline splits on the dividers first, then applies size limits. Blind size cuts make fragments, and no embed model or larger top-k repairs a broken boundary. The repair order in the source case is fixed: fix the boundary rule first.

    From the lesson§4 · Binary vectors and FP16 quantization

    Vector embeddings are float32, at 4 bytes per dimension. Quantization stores each dimension in fewer bits. Binary vectors use 1 bit per dimension, a 32 times cut. FP16 scalar quantization uses 16 bits, a 2 times cut. The trade is a small accuracy loss for large memory and cost gains in the index, and index memory is often the top cost in a RAG system. The source example runs one vector at 1,536 dimensions: 6,144 bytes at full precision. Ten million such vectors take 60 GB. The binary form takes 1.875 GB, and a full-precision rerank step guards the accuracy cost, which the example puts at about 2 percent.

    32x smaller the binary index against float32, section 4 worked example Nugget 6 · From the lesson §4 · Binary vectors and FP16 quantization The lesson Binary quantization cuts a 60 GB vector index to 1.875 GB: a 32 times cut for about 2 percent accuracy in the source example. Why it matters. Index memory can drop a full instance class. The full-precision rerank step buys back the accuracy the cut spends. Transfer. Measure the accuracy cost on your own data, as the source warns. A vendor example is a hypothesis, not a result. UNIT 07 · AIP-C01

    From the lesson§4 · SageMaker tuning and EMR

    SageMaker large-model tuning specifics cover the deployment-time decisions for large custom models: how a big model trains, tunes, and lands on an endpoint under SageMaker control. The ladder map files this entry as a deployment-time decision, apart from the inference-time primitives of the prior chapter. Amazon EMR is a managed big-data platform that runs open-source distributed frameworks: Apache Spark, Hadoop, Hive, Presto and Trino, HBase, and Flink. Three forms exist: EMR on EC2, EMR on EKS, and EMR Serverless, where you submit a Spark or Hive job with no cluster to manage. GenAI pipelines need EMR-scale data work: dedupe of billions of web documents, click-log joins, and bulk embed runs ahead of index build.
