    Lab 1: Strands agent with custom tools

    From the lesson Lab 1 · What this lab teaches

    Mechanism

    From the lessonLab 1 · What this lab teaches

    This lab teaches a work agent in a few lines of Python: one model, a tool list, a system prompt, and a custom function the model can call. Strands Agents is an open-source Python SDK. An agent has three parts: a model as the brain, tools as the hands, and a prompt as the personality and instructions. You create an Agent, give it tools, and call it with a question like a function. No prerequisites: this lab is the start point.

    From the lessonLab 1 · Why it exists

    You use this pattern in production when you want code control of the loop. The diagram in the source draws the exam line: code control means Strands, a managed loop means Bedrock Agents. AWS hosts the Bedrock loop and you configure it. With Strands you write the loop host code yourself.

    From the lessonLab 1 · How it works

    The agent loop is the core idea. A single model call cannot use tools alone, so the SDK runs a cycle. Send the prompt to the model. The model replies with text or with a tool call request. The SDK runs the tool and returns the result to the model. The cycle repeats until the model gives a final answer. Strands is model-driven: the model picks the tool at each step. A custom tool is a plain Python function with the tool decorator. The docstring becomes the tool description that the model reads, and the type hints become the input schema.

    3 parts model, tools, and prompt form one Strands agent, Lab 1 Nugget 1 · From the lesson Lab 1 · How it works The lesson The docstring is route logic, not documentation. A vague docstring makes tool selection random, because the model picks tools from the description text. Why it matters. An agent has three parts: model, tools, prompt. The tool part lives or dies on description quality, and the description is prose you write. Transfer. Write tool descriptions for the reader who acts on them. In agent systems, that reader is a model under time pressure. UNIT 02 · AIP-C01

    IllustrationLab 1 · Step-through

    Open the four beats of the agent loop in order.

    Beat 1 · Send

    The SDK sends the prompt, the tool list, and the system prompt to the model.

    Beat 2 · Decide

    The model answers with text or asks for a tool call. The model makes this pick at each step.

    Beat 3 · Run

    The SDK runs the tool function with the model arguments and holds the result.

    Beat 4 · Return or repeat

    The result goes back to the model. The loop repeats until the model gives a final answer.

    Lab 2: Bedrock Flows from JSON

    From the lesson Lab 2 · What this lab teaches

    Mechanism

    From the lessonLab 2 · What this lab teaches

    This lab teaches a chain of prompts as a real flow definition, with nodes, connections, and conditions. The lab prompt list names a city, describes it, and describes its food. In a flow, each prompt becomes a Prompt node. No agent code is a prerequisite: you define the flow as JSON.

    From the lessonLab 2 · Why it exists

    Some workflows must not use model judgment. They must run the same steps each time. This lab trades agent freedom for a fixed path: a deterministic prompt pipeline for production work with an audit shape.

    From the lessonLab 2 · How it works inside

    Amazon Bedrock Flows build deterministic multi-step GenAI workflows. A flow definition has two arrays: nodes and connections. Node types cover Input and Output, Prompt for one model call, Agent for a step handed to an agent, KnowledgeBase for a retrieval step, Condition for a branch on logic, Iterator for a loop over a list, LambdaFunction for custom code, plus storage nodes. A connection is Data or Conditional. A Data connection moves a named output to a named input. The path never changes at runtime, apart from the branches a Condition node states.

    2 arrays nodes and connections define one flow, Lab 2 Nugget 2 · From the lesson Lab 2 · How it works inside The lesson A flow is two arrays: nodes for the steps and connections for the wires. The fixed path is the point, and the model gets no route vote. Why it matters. A KnowledgeBase node pulls answers from your documents via RAG, so a flow can ground a step with no agent at all. Transfer. Pick the control form per risk: a fixed path where variance is a defect, an agent where variance is the work. UNIT 03 · AIP-C01

    Lab 3: multi-agent squad routing

    From the lesson Lab 3 · What this lab teaches

    Mechanism

    From the lessonLab 3 · What this lab teaches

    This lab teaches one entry point in front of many specialist agents. A classifier reads each request and routes it to the correct specialist. The prerequisite is Lab 1: the Strands agent registers here as a specialist.

    From the lessonLab 3 · Why it exists

    Real systems need several specialists behind one door. A billing agent, a support agent, and a general assistant use unlike tools, prompts, and knowledge. One large agent for all work blurs each edge.

    From the lessonLab 3 · How it works under the hood

    Agent Squad is an open-source multi-agent framework, and the pip package name is agent-squad. You register specialist agents with one orchestrator. The classifier is most often a small fast model. It picks the best specialist, the orchestrator hands the request over, and the answer returns with route metadata. A ChainAgent runs a fixed pipeline across agents. A SupervisorAgent coordinates workers. Chat history sits in a ChatStorage layer: in-memory by default, DynamoDB or SQL for production. A fourth specialty means one more registration, not a router rewrite. The pattern also mixes frameworks: a Strands agent, a plain Bedrock model agent, and a Lambda agent can sit behind one classifier.

    1 entry point many specialists behind one classifier, Lab 3 Nugget 3 · From the lesson Lab 3 · How it works under the hood The lesson One entry point, many specialists, one classifier. Growth adds a registration, and the route layer stays the same size. Why it matters. Specialists beat generalists as scope grows, because each specialist holds a tight tool set and a tight prompt. Transfer. Route at the edge and specialize at the core. A router that knows each job in detail becomes the bottleneck it was meant to remove. UNIT 04 · AIP-C01

    Lab 4: Lambda as Bedrock front end

    From the lesson Lab 4 · What this lab teaches

    Mechanism

    From the lessonLab 4 · What this lab teaches

    This lab teaches a stable HTTP front door for model calls: API Gateway for the endpoint and Lambda for the logic. The lab introduces Lambda, API Gateway, and AppConfig from zero, so basic AWS knowledge is the only prerequisite.

    From the lessonLab 4 · Why it exists

    Labs 1 to 3 ran on a laptop. Production needs the front door first, and each later lab uses this serve path. A direct call from a browser or phone sends AWS credentials to the client and gives each client direct model access. The front end keeps credentials on the server side and throttles per client at the gateway.

    From the lessonLab 4 · How it works

    Lambda is serverless compute: you upload a function, AWS runs it on events, and you pay per run. API Gateway is the managed front door: a stable HTTPS endpoint with auth, throttles, and route rules. The lab handler shows the Lambda proxy integration shape. The handler takes an event, does work, and returns a dictionary with statusCode, headers, and a JSON-string body. API Gateway turns that dictionary into the HTTP response. The full path runs client, gateway auth and throttle, Lambda checks, model select, Bedrock call, answer back.

    3 fields statusCode, headers, and body in the proxy response, Lab 4 Nugget 4 · From the lesson Lab 4 · How it works The lesson The proxy response has three fields: statusCode, headers, and a body that holds a JSON string. That dictionary is the whole contract with the gateway. Why it matters. The hello-world handler in the lab is the base structure. A Bedrock call slots into the same shape, so Lab 5 can reuse it for agent actions. Transfer. Learn the platform contracts as exact shapes. Most integration defects are shape defects, not logic defects. UNIT 05 · AIP-C01

    Lab 5: Lambda as agent action

    From the lesson Lab 5 · What this lab teaches

    Mechanism

    From the lessonLab 5 · What this lab teaches

    This lab teaches the exact request and response contract that Bedrock Agents use to call your code. The weather function in the lab shows the event the agent sends and the response the agent expects. The prerequisite is Lab 4, because action-group Lambdas reuse the handler shape.

    From the lessonLab 5 · Why it exists

    Lab 4 made Lambda serve the client. This lab makes Lambda the hands of the agent. An agent with no action groups can talk and cannot act, and this contract is the act path.

    From the lessonLab 5 · How it works under the hood

    An action group links the agent to a Lambda and to a schema. Two schema styles exist: function details, a list of named functions with parameters, and an OpenAPI schema for REST-style operations. The lab weather code uses function details, with a get_weather function that takes a city and units. The event carries the agent name, the action group name, the function name, a parameters list with name, type, and value entries, and a messageVersion. The response echoes the action group and function and wraps the result in the response body text field. With an OpenAPI schema, the event carries apiPath and httpMethod, and the response carries an HTTP status code.

    2 halves a structured event in and an echo response out, Lab 5 Nugget 5 · From the lesson Lab 5 · How it works under the hood The lesson The contract has two halves: a structured event in, and an echo response out. One wrong field name and the action fails. Why it matters. The response must carry messageVersion and the same action group and function names as the request. The agent trusts the echo, not your intent. Transfer. Echo contracts fail silent and total. Test the exact field names with one real call before you test the logic. UNIT 06 · AIP-C01

    Lab 6: AgentCore Runtime deployment

    From the lesson Lab 6 · What this lab teaches

    Mechanism

    From the lessonLab 6 · What this lab teaches

    This lab teaches the ship step: containerize the laptop agent, meet the runtime contract, and let AgentCore host the agent with sessions, tools, memory, and identity. Prerequisites are Lab 1 for the Strands agent and Lab 5 for the Bedrock Agents base.

    From the lessonLab 6 · Why it exists

    A laptop agent serves no users. Production needs a host that adds sessions, memory, identity, and traces around your code, and AgentCore is that host.

    From the lessonLab 6 · How it works under the hood

    Amazon Bedrock AgentCore is the managed platform for agents in production, with five parts. Runtime is serverless host for your agent container. Gateway turns your APIs and Lambda functions into MCP tools. Memory holds short-term and long-term agent context. Identity is agent auth with access to third-party apps. Observability is trace and monitor support with OpenTelemetry. The Runtime talks to your container over plain HTTP with a fixed contract. The bedrock-agentcore Python SDK gives a small wrapper app, and you mark one function as the entrypoint.

    5 parts Runtime, Gateway, Memory, Identity, Observability in Lab 6 Nugget 6 · From the lesson Lab 6 · How it works under the hood The lesson AgentCore has five parts to name on sight: Runtime, Gateway, Memory, Identity, Observability. Why it matters. The exam tests the five-part list and the Runtime contract as one unit. A miss on either half marks the whole answer wrong. Transfer. Name the platform parts before you use the platform. A part list is a checklist for the needs your own code must not rebuild. UNIT 07 · AIP-C01

    Port 8080 the AgentCore Runtime HTTP contract, Lab 6 Nugget 7 · From the lesson Lab 6 · Verification log The lesson The Runtime contract is plain HTTP on port 8080: POST to the invocations path runs the agent, and GET to the ping path reports health. Why it matters. The verification log in the source confirms the contract, with the linux/arm64 build target, against the official AgentCore developer guide. Transfer. A fixed contract is a gift: two routes and one port decide pass or fail before any agent logic runs. UNIT 07 · AIP-C01

    Lab 7: supporting labs, KMS, X-Ray, SQS, and foundations

    From the lesson Lab 7 · What this chapter covers

    Mechanism

    From the lessonLab 7 · What this chapter covers

    This chapter covers the infrastructure under the agents: encryption, traces, queues, and the base building blocks of each GenAI architecture. The support exercises are not GenAI-specific, and each one gets its exam frame here. No file stays unmapped. KMS manages the keys that protect data at rest, and the lab CLI script shows the envelope pattern: encrypt a file with a KMS key, store the ciphertext, decrypt it back with the same key. In GenAI systems, KMS keys encrypt fine-tune datasets in S3, Bedrock invocation logs, and flow definitions. The exam tests customer-managed keys for sensitive train or log data, and VPC endpoints for private paths. X-Ray covers traces, SQS covers queues, and one thread ties the chapter to RAG: the book and bylaws files in the pack are raw material for a knowledge base pipeline.

    3 steps the KMS envelope pattern in Lab 7 Nugget 8 · From the lesson Lab 7 · What this chapter covers The lesson Envelope encryption runs three steps: KMS makes a data key, the data key encrypts the data while KMS encrypts the data key, and CloudTrail logs each KMS use. Why it matters. The master key never touches the bulk data. Key rotation and audit stay cheap, and the data path stays fast. Transfer. Encrypt the key, not the world. One small protected object can guard a large plain object store. UNIT 08 · AIP-C01

    From the lesson Lab 8 · What this lab teaches

    Mechanism

    From the lessonLab 8 · What this lab teaches

    This lab teaches the full GenAI stack as code in a real language, with a compile step to CloudFormation. Prerequisites are Lab 4 for the serve path and Lab 7 for the services.

    From the lessonLab 8 · Why it exists

    Lab 4 built the serve path by hand. Hand builds drift. This lab makes the stack repeatable, open to review, and ready for audit.

    From the lessonLab 8 · How it works under the hood

    The AWS Cloud Development Kit lets you define cloud infrastructure in TypeScript or Python. Constructs are the small blocks: a Lambda, an S3 bucket, a DynamoDB table. Blocks combine into a stack. The synth command compiles code to a CloudFormation template. The diff command shows the change for review before deploy. The lab stack builds an uploads bucket, a Lambda with an IAM role, and a DynamoDB table, with outputs that link the parts. CDK pays off most at IAM: the Lambda role gets the InvokeModel action on named model ARNs, plus log rights, and no more.

    12 resources a production GenAI service with its links, Lab 8 Nugget 9 · From the lesson Lab 8 · How it works under the hood The lesson A production GenAI service has about 12 resources with links: the function needs the table name, the role needs the model ARNs, the gateway needs the function. Why it matters. Hand clicks lose those links. Code holds them as values that the synth step checks before any deploy. Transfer. Codify the links, not just the parts. System defects live in the links.     Lab 9: CI/CD with eval gates

    From the lesson Lab 9 · What this lab teaches

    Mechanism

    From the lessonLab 9 · What this lab teaches

    This lab teaches prompt and model changes shipped like code: pipeline stages, build specs, an evaluation gate, and canary rollout before production. Prerequisites are Lab 2 and Lab 5 for flows and agents, and Lab 7 for the evaluation words.

    From the lessonLab 9 · Why it exists

    Teams edit prompts in the console and paste them into production, and silent regressions follow. A reworded system prompt can stop refusal behavior. A model swap can shift tone. A new few-shot example can bias outputs. The pipeline makes each change pass a test first.

    From the lessonLab 9 · How it works

    CI/CD on AWS is a pipeline of stages: source, build, test, deploy. CodePipeline controls the stages. CodeBuild runs the build under a buildspec file with four phases: install, pre_build, build, post_build. CodeDeploy sends the artifact to its target. For GenAI, the build phase holds the evaluation gate. The gate runs an evaluation suite, compares metrics with thresholds, and fails the build on a regression. The bad prompt gets a red build, not a production incident.

    4 phases install, pre_build, build, post_build in the buildspec, Lab 9 Nugget 10 · From the lesson Lab 9 · How it works The lesson A buildspec runs four phases: install, pre_build, build, post_build. The eval gate lives in the build phase, where a fail still costs zero users. Why it matters. A prompt change is a behavior change, and behavior needs tests. The gate turns a silent regression into a loud build failure. Transfer. Gate at the last cheap point. Each stage past the gate raises the price of the same defect. UNIT 10 · AIP-C01
