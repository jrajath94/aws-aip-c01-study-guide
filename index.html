    Outer layer Claim

    What this exam is really about

    Generative AI on AWS means one thing: you call large AI models through managed AWS services.

    Mechanism

    Generative AI on AWS means one thing: you call large AI models through managed AWS services. You do not train or host the models yourself. A foundation model is a large model pre-trained on broad data. You adapt it instead of building from scratch. Amazon Bedrock is the managed AWS service that serves foundation models from many providers through one set of APIs. You never manage GPUs.

    Most exam questions are variations on three moves. First, grounding the model in your own data. RAG (retrieval-augmented generation) fetches relevant documents at answer time, and the model answers citing them. Second, wiring the model into real applications: agents that take actions through tools, and Lambda functions that connect services. API Gateway endpoints face users. Third, guarding it all: guardrails that filter harmful or off-policy content, and IAM policies that control who can call what.

    The rest is day-to-day operation. Pick the right model for the cost. Cache repeated work and measure quality with evals. Evals are structured tests of model behavior. Debug what breaks. With that shape in mind, the vocabulary below reads as names for things you already understand, not jargon.

    How to read this diagram. 1. GROUND: the system fetches documents at answer time, and the model cites them. This is RAG. It exists because the model does not know your private data. If retrieval fails, the model hallucinates. 2. WIRE: agents, Lambda, and API Gateway connect the model to real applications. This exists because a model alone cannot act. If the wiring breaks, answers never reach users. 3. GUARD: guardrails filter content, and IAM controls who can call what. This exists because unsafe output and open access are failures. If guards fail, the system leaks or harms. The bottom bar is operations: pick the right model, cache repeated work, eval quality, debug what breaks.

    How to read this diagram. 1. Foundation models from many providers enter from the left. They exist so you never train or host models yourself. If one model is unavailable, pick another through the same API. 2. Amazon Bedrock sits in the center with one set of APIs. It exists to unify access across providers. If Bedrock is misconfigured, no calls succeed. 3. Two APIs leave to the right. Converse is the unified text-generation API. InvokeModel sends the provider's raw body and is the only path for embeddings. Pick Converse for chat; pick InvokeModel for embeddings.

    Terms you will meet

    One-line definitions for the vocabulary every volume assumes. Each term is taught in depth where it is first used.

    Mechanism

    One-line definitions for the vocabulary every volume assumes. Each term is taught in depth where it is first used. This is only so every word on this page is clear.

    Tokens become embeddings. Embeddings live in a vector store. The store powers RAG. Knowledge Bases, agents, guardrails, and inference sit on top. Every volume assumes these. Each is taught in depth where first used.

    Foundation model A foundation model is a large model pre-trained on broad data. You adapt it for tasks instead of training it from scratch. Amazon Bedrock Amazon Bedrock is the managed AWS service that serves foundation models from many providers through one set of APIs. Token A token is the unit the model reads and writes. AWS bills by tokens. A token is roughly a word fragment, about 4 characters of English. RAG Retrieval-augmented generation. The system looks up facts from your documents at answer time. The model then cites those facts. Knowledge Base Knowledge Bases is Bedrock's managed RAG service. Point it at documents. It handles chunking, embedding, and retrieval. Embedding An embedding is a vector of numbers that captures meaning. Similar meanings sit close together. Vector store A vector database holds embeddings. It returns the embeddings nearest to a query, fast. Agent An agent is a model paired with instructions and tools. It reasons over a goal and decides which tools to call. Guardrail A guardrail is a named Bedrock configuration that holds safety rules. It holds content filters, denied topics, PII filters, and grounding checks. Fine-tuning Fine-tuning retrains parts of a model on labeled examples. This builds a behavior such as tone or format into the model. Inference Inference runs a trained model to produce an answer. Almost everything on this exam is inference, not training. Latency / throughput Latency is how fast one answer comes back. Throughput is how many answers you get per unit of time. Provisioned Throughput You reserve Provisioned Throughput as inference capacity. You buy it by the hour for steady production baselines. Converse / InvokeModel These are the two Bedrock call APIs. Converse is the unified text-generation API. InvokeModel sends the provider's raw body. It is the only path for embeddings. IAM IAM is AWS Identity and Access Management. Its policies decide which identity can do what. KMS KMS is AWS Key Management Service. It manages encryption keys for data at rest.

    Top pitfalls candidates report

    Read the last sentence first, eliminate two options fast, decide between the last two. Flag at 2.5 minutes and move on.

    Mechanism

    Read the last sentence first, eliminate two options fast, decide between the last two. Flag at 2.5 minutes and move on. The review pass is for flagged questions.

    1. Time pressure is the real enemy. Read for shape, then read again for the constraint. Eliminate two answers fast. Decide between the last two. If you are undecided at about 2.5 minutes, flag the question and move on. Do not count on review time.
    2. "Least operational overhead" is the most repeated phrase. Read it as "fewest services you manage yourself." Managed and serverless options beat clusters and custom Lambda wiring.
    3. Multi-response questions need coherent pairs. Each chosen option solves a different part of the problem. The pair must form a coherent design.
    4. Proactive vs reactive. If the requirement says "proactively," eliminate every option that only detects or reacts after the failure.
    5. Fabricated features in wrong answers. Candidates found three fabricated features. They were "S3 action nodes in Bedrock Flows," "Guardrails with token quota policies," and "cross-region guardrail replication." If an option looks slightly wrong, the feature may not exist.
    6. Know what services cannot do. Guardrails cannot enforce IAM access. Macie scans S3, not CloudWatch Logs. AppSync is synchronous. Negative facts eliminate wrong answers faster than positive facts select right ones.
    7. Express Step Functions: 5-minute max, no Wait for Callback. Human-approval pauses need Standard Step Functions.
    8. CloudTrail vs CloudWatch for safety auditing. CloudTrail records who called which API. It does not capture what a guardrail blocked or why. That data goes through CloudWatch custom metrics.
    9. Safety threads through all domains. A Domain 2 question can hinge on a guardrail behavior from Domain 3. Do not study domains in isolation.
    10. The center of gravity is Bedrock, not SageMaker. There are no confusion matrices, no feature engineering, and no SageMaker training pipelines. SageMaker shows up via JumpStart, alternative hosting, and Clarify-style evaluation.

    How to read this diagram. 1. Read for shape: skim the scenario. 2. Read again for the constraint: the one requirement that decides. 3. Eliminate two answers fast. 4. Decide between the last two. The orange bar is the time rule: if you are undecided at about 2.5 minutes, flag the question and move on. Do not count on review time.

    Mechanism

    For candidates who can give 4+ hours a day over four weeks and want the lab-first path the passers recommend. Plan roughly 2 hours of lab, 1.5 hours of course or video, and 30-60 minutes of practice questions and docs per day. Set up a personal AWS account with billing alarms on day one.

    Days 1-2: Foundation. Read the official exam guide end to end. Skim the Well-Architected GenAI Lens overview. Take one untimed practice set with no preparation to find your baseline.

    Week 1: D1, RAG core (31%). Run the hands-on set from "What actually helped" #1 above. It covers a Knowledge Base, all four chunking strategies, and both vector stores. It covers an agent with action groups and guardrail probing.

    Then drill the decision the exam tests most: OpenSearch vs Aurora pgvector vs MemoryDB vs S3-with-metadata, driven by scale, latency, and operational overhead. The trio of Agents, Knowledge Bases, and Guardrails is central. Expect 8-10 questions touching some combination.

    Week 2: D2, implementation and agents (26%). Build a Bedrock Agent with Action Groups backed by Lambda. Build a multi-step workflow with Prompt Flows (Bedrock's visual no-code workflow builder). Compare orchestration: Step Functions Standard vs Express. Express caps at 5 minutes and has no Wait for Callback. Compare delivery: API Gateway response streaming vs WebSockets.

    Practice the right-tool-for-data rule. Use Knowledge Bases for unstructured documents. Use text-to-SQL for RDS. Never embed relational tables into a vector store.

    Week 3: D3 safety and governance (20%) + D4 cost and performance (12%). Configure Guardrails end to end: content filters, denied topics, PII redaction, contextual grounding, and detect-only vs block modes. Probe them with adversarial prompts. Study SCPs (org-level permission ceilings) vs IAM permissions boundaries (per-role limits) for multi-account Bedrock governance, KMS, TLS, and PrivateLink.

    For D4: on-demand vs provisioned throughput, prompt caching, smaller-model routing, CloudWatch Bedrock metrics, and X-Ray tracing for agent workflows.

    Week 4: D5 evaluation and troubleshooting (11%), then timed practice. Learn Bedrock model evaluation, LLM-as-a-judge patterns, retrieval precision and recall debugging, and hallucination detection via grounding checks. Learn the common failure list: context overflow, token limits, embedding mismatch, prompt injection bypass, and throttling.

    Then take full-length exams under real time pressure, targeting the 85% booking bar.

    ADHD-friendly structure: Do labs before videos: build first, then learn the name for what you built. Use one question card at a time with the "why is this option wrong" drill. Use 25-minute timers per scenario set.

    End each day by writing the one decision rule you learned in your own words.
