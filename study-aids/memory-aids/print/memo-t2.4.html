Memory sheet: Task 2.4 Implement FM API integrations

Domain 2, weight 26 percent. Read this sheet, then answer the flash questions aloud.

Deciding rules

Etch lines

  1. Streamed replies need a REST API with a proxy integration and STREAM mode.
  2. Keep the circuit record shared across executions, so each one sees the failure.
  3. Send slow work to SQS when the caller accepts a later result.
  4. An interface endpoint with private DNS on keeps the SDK code unchanged.
  5. A NAT gateway path still uses the internet gateway, which the rule forbids.
  6. Max attempts counts the first call, so a value of 3 allows two retries.

Flash questions

  • Q: Which API type can stream a model reply through a proxy integration? A: A REST API with STREAM transfer mode, since HTTP APIs lack response streaming.
  • Q: Which front door fits a browser that must send messages while the server also pushes updates? A: A WebSocket API with a route for each message type.
  • Q: What does the max attempts setting count? A: The first call plus retries, so a value of 3 allows two retries.
  • Q: Which network option keeps bedrock-runtime traffic off every internet path? A: An interface endpoint with private DNS on, not a NAT gateway.
  • Q: A caller can take a job ID now and the answer later. Which pattern fits? A: Accept the request, queue it in SQS, and let a worker call the model.
  • Q: Does a 429 from API Gateway prove that Bedrock quota ran out? A: No, the gateway returned it before the backend ran.
  • Q: Where should circuit state live when many executions call one failing dependency? A: In shared storage such as DynamoDB, which a Choice state reads before each call.
  • Q: Which Step Functions state tests request fields to pick a model branch? A: A Choice state, which needs a Default branch for unmatched input.
