    Pattern 1: Constraint extraction

    How to read this diagram.

    1. Read the stem and underline each hard constraint.
    2. Read option A against every constraint.
    3. If an option violates even one constraint, eliminate it.
    4. The option that survives every constraint is the answer.
    5. Check the trap name in the explanation.

    Why this chapter comes next. You extract the constraints. The next pattern selects between the options that meet the constraints. It finds the most correct option, not only a correct option.

    Each stem has 2 to 4 hard constraints. Examples are cost, latency, no ML team, no redeploy, region lock. The correct answer is the only option that meets ALL constraints. Underline each constraint before you read the options. Then remove any option that does not meet one constraint.

    Pattern 2: MOST correct, not merely correct

    Why this chapter comes next. You select the winner. Pattern 3 checks a different error. It checks steps in the wrong order.

    Two or three options will work. The tiebreakers select the winner in this order. Prefer managed service over custom build. Prefer cheaper over more expensive at the same quality. Prefer simpler architecture over complex architecture. Prefer AWS-native over third-party. If you cannot decide, ask this question: Which option would an AWS solutions architect defend in a review?

    Pattern 3: Ordering and lifecycle

    How to read this diagram.

    1. Find the lifecycle in the stem: agent, model, or build.
    2. Anchor the first step and the last step.
    3. Read the order each option proposes.
    4. Eliminate any option that inverts the order.
    5. Use the middle steps only to break ties.

    Why this chapter comes next. You verify the order. Pattern 4 tests if you know which lever solves which problem. This is vocabulary precision.

    Follow the real service lifecycle. First, configure. Then, prepare. After that, test. Select a model before you customize it. Scope before you build. An option that changes the lifecycle order is incorrect.

    Pattern 4: Vocabulary precision.

    Why this chapter comes next. Terms are precise. Pattern 5 is the default approach. Use managed services first. Climb the ladder only as far as necessary.

    AWS tests your knowledge of solutions for problems. An inference profile is a routing ID. It works across regions. It gives a model better availability. It gives higher effective quotas. Call the profile ID. Do not call the bare model ID. A prompt router (Bedrock's model router) sends each request to a cheap model or a flagship model. It bases this on prompt complexity. Provisioned Throughput reserves model capacity. You pay for it by the hour. It has latency guarantees. ApplyGuardrail runs a guardrail. It is a standalone policy check on any text. It works outside a model call. returnControl pauses an agent. It gives control back to your code. This is the hook for human approval gates. If two options sound similar, the difference is one precise term.

    Pattern 5: Managed-first and the ladder.

    Why this chapter comes next. You climb the ladder. The last pattern names the distractors directly. These are real services that do the wrong job.

    Use the managed service by default. Climb the capability ladder only until you meet the requirement. Use prompt engineering. Then, use RAG. After that, use agents. Then, use fine-tuning. Options that go directly to training or custom builds fail the overhead filter.

    Pattern 6: Wrong-plane distractors.

    How to read this diagram.

    1. Read what the option offers: a service name.
    2. Ask what that service actually does.
    3. Ask what job the stem needs.
    4. If the two jobs differ, eliminate the option.
    5. Pick the service whose real job matches the stem.

    Distractors name real services that do the wrong job. For example, Guardrails for extraction. Knowledge bases for live API calls. CloudFormation for runtime configuration. Encryption for network isolation. Ask this for every option: Is this service's actual job the job the stem needs?

    Terms you will meet. Read this one time. Every question below uses only these meanings.

    • RAG (retrieval-augmented generation): The model answers from passages. The model gets the passages from your documents at query time. It does not get the passages from its training. A knowledge base is Bedrock's managed RAG. It stores, retrieves, and cites.
    • Fine-tuning: Train a base model more on your labeled data. This makes the model do a specific behavior. LoRA is the low-cost form. It trains small adapter weights. It does not train the whole model.
    • Chunking: Split documents into pieces for retrieval. Fixed-size chunking uses uniform windows. Semantic chunking splits at meaning boundaries. Hierarchical chunking keeps parent-child context.
    • Embedding: An embedding is a list of numbers (a vector). It shows a text's meaning. Its length is its dimensions. A vector store is the database. It holds embeddings for similarity search.
    • Prompt caching: This is a billing discount for repeated long prefixes. A cachePoint marks the end of the cacheable prefix.
    • Converse API: This is Bedrock's unified request format. It is for text generation and tool use across providers. It cannot do embeddings. Use InvokeModel for embeddings.
    • Agent: An agent is a model. It reasons in a loop and calls tools. An action group is how a Bedrock agent gets a tool. It is a Lambda function or an OpenAPI schema with a parameter contract.
    • Guardrail: This is Bedrock's content-safety filter. It has content filters, denied topics, word filters, and sensitive-information filters. guardrailConfig is its inline field on a Converse call.
    • Faithfulness: This is whether the answer's claims have support from the retrieved passages. Citation precision is the share of citations. These citations must support the cited claim.
    • LLM-as-a-judge: This is a second model. It scores outputs on quality dimensions. These dimensions are faithfulness, tone, and harmfulness. A2I (Augmented AI) is Amazon's human-review workflow for flagged cases.
    • Temperature: This is the sampling randomness knob. 0 is deterministic.
    • Automated Reasoning: This is Bedrock's deterministic checker. It validates an output against formal policy rules.
    • Data residency: This is the requirement. Data must stay inside a chosen region or country.
    • VPC endpoint: This is a private network path. It goes from your VPC to an AWS service. It has no public internet.
    • SCP (service control policy): This is an organization-wide permission ceiling. A permissions boundary limits one role's maximum permissions.
    • Macie finds PII in S3 data at rest. Comprehend detects PII in text inline.
    • Task token: This is a callback handle. Step Functions gives it to your code. A human approval can pause and resume a workflow.
    • Red-teaming: This is adversarial testing. People try to break the model's safety on purpose.
    • ROUGE and BLEU are automatic metrics. They compare a generated text's word overlap with a reference. They are fast but shallow.
    • ZeRO is a training technique. It shards optimizer state across GPUs. This saves memory.
    • Blueprint (Bedrock Data Automation) is a template. It names the fields to extract from documents.
    • Human-in-the-loop: A person approves the output before the output goes out. Human-on-the-loop: Outputs go out. A person monitors the outputs after.
    • HNSW and IVFFlat are approximate nearest-neighbor indexes. They provide fast vector search. Flat exact search checks every vector. It is exact but slow.
    • Erasure is a deletion. The deletion must cover derived data. This includes embeddings in the vector index.
    • FSx for Lustre is a high-throughput parallel file system on AWS. An S3 dataset often backs it. It feeds training jobs data fast enough to keep GPUs busy.
    • SageMaker Model Registry is the catalog. You register trained model versions here. They have metadata and approval status before deployment.
    • SageMaker Experiments is the tracker. It records hyperparameters, code versions, and dataset references for each training run. This makes results reproducible.
    • Bedrock Marketplace is the Bedrock catalog. Use it to find and subscribe to third-party models. The deployer still owns safety evaluation and guardrails.
    • Distributed Map is a Step Functions state. It fans out to 10,000 parallel child executions. This occurs over a dataset such as S3 objects.

    Mechanism

    Why this chapter comes next. Tactics tell you how to attack. The trap catalog tells you what attacks you. AWS reuses 30 distractors. You can name each one on sight.

    1. Lambda 15-minute timeout: Any option with a Lambda waiting, sleeping, or polling for a long task fails. Go async or use Step Functions.
    2. Custom code vs managed: The stem says no ML team or least effort. Custom builds lose to Bedrock managed features.
    3. Knowledge base scope: Knowledge bases serve documents. They never call APIs. They never enforce access control. They never execute actions.
    4. Fine-tuning for fresh data: Changing documents or a need for citations means RAG. Never use fine-tuning.
    5. Capacity confusion set: Use inference profiles for availability. Use prompt routers for cost by complexity. Use Provisioned Throughput for reserved capacity. Do not mix them.
    6. Guardrails wrong plane: Guardrails filter content. They do not extract data. They do not enforce tenant isolation. They do not replace IAM.
    7. Ladder jumping: The cheapest option that meets the requirement wins. Premium features lose if there is no stated need.
    8. CloudFormation for runtime config: A stack update is a deployment. AppConfig provides runtime switching without redeploys.
    9. ElastiCache as storage: ElastiCache is ephemeral caching. Durable vectors live in a vector store.
    10. Residency blindness: Cross-region failover is wrong when the stem requires data residency. Check the region constraint first.
    11. Prompt Management plus guardrailConfig: Converse rejects that combination. ApplyGuardrail standalone is the workaround.
    12. Missing prepare step: You need to prepare agent configuration changes before testing. If the behavior is the same after a change, you skipped prepare.
    13. Misleading AccessDenied: Check model availability in the region before you debug permissions.
    14. Converse for embeddings: Converse is for text generation only. Use InvokeModel for embeddings.
    15. Built-in safety is enough: Alignment and guardrails do not transfer the deployer's responsibility to evaluate and govern.
    16. Proactive vs reactive: If the stem says "proactively," delete every option that reacts after failure. Token-limit alerts mean counting tokens before the call. They do not mean alarming after the call.
    17. Fabricated features: This is a real service with a capability it does not have. Examples are S3 nodes inside Bedrock Flows, Guardrails enforcing token quotas, and cross-region Guardrail replication. If an option sounds incorrect, check if the feature exists.
    18. Audit trail three-way: CloudTrail shows who called which model. CloudWatch custom metrics show which prompts the guardrail blocked and why. Model invocation logging (opt-in) shows prompt and response content. Prompts never carry CloudTrail.
    19. Step Functions Standard vs Express: Express caps at 5 minutes. It cannot wait for callbacks like human approval or long pauses. High concurrency never beats a duration or pause constraint. Use Standard for callbacks.
    20. Sequential vs parallel: Tight windows over many objects mean Step Functions Distributed Map. This supports up to 10k parallel children over S3. Lambda-only fails on the 15-minute timeout. Sequential fails on the clock.
    21. Vector store by scale: Small data goes to Aurora Serverless with pgvector. This has the least overhead. Medium to large data goes to OpenSearch with IVFFlat or HNSW. Small data with a 100 percent recall requirement needs flat exact search. It does not need HNSW.
    22. Perceived vs real latency: If users report slow responses with unique interactions, use streaming (ConverseStream). Do not use Provisioned Throughput. Do not use prompt caching. Provisioned Throughput fixes capacity. Caching needs repeated prefixes. Neither speeds the first token.
    23. Prompt caching precondition: Caching is useful only with repeated long prefixes. This means the same system prompt and the same large context. Unique interactions make it dead weight. Check the repetition sentence before you select it.
    24. Provisioned throughput misuse: Idle PT and throttled on-demand calls mean the code uses a base model ID. It does not use the provisioned model ARN. Fine-tuned models must use PT. They cannot use on-demand.
    25. Guardrail detect versus block: "Notify if bad content appears but do not block" is detect mode. It is not a blocking filter. Detection without blocking is a mode choice. It is not a different service.
    26. SCP versus permissions boundary: Org-wide model restrictions are SCPs. They set maximum permissions. This includes requiring an approved guardrail on InvokeModel. Permissions boundaries limit individual roles. One mechanism alone is the trap. The full answer uses both mechanisms.
    27. PII pipeline order: Macie finds PII in S3 at rest. Comprehend finds PII in text inline. Guardrails redact or block at invocation time. The pipeline is: Comprehend detects, then redacts, then Bedrock. Macie never scans logs. Guardrails never discover.
    28. No public internet: Use interface VPC endpoints for Bedrock. Use Lambda in private subnets. A NAT gateway option breaks the constraint. This is true even if other parts are correct.
    29. Evaluation ladder: Automatic metrics screen at low cost. LLM-as-judge scores quality at scale. Humans review only the best candidates. A2I is for flagged critical interactions. It is not for all traffic. Provider benchmarks alone never decide.
    30. Adjective precision: "Least custom development effort" means managed features. It does not mean Lambda code. "Least operational overhead" means the fewest self-managed components. "Most cost-effective" means token math. This means a smaller model, caching, and batch. Three adjectives mean three different best choices. Read the exact word.
