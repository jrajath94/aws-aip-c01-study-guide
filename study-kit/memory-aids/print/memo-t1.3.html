Memory sheet: Task 1.3 Implement data validation and processing pipelines for FM consumption

Domain 1, weight 31 percent. Read this sheet, then answer the flash questions aloud.

Etch lines

  1. Read the data type and the consumer before reading any option.
  2. Run checks so a bad record never reaches the embedding step.
  3. A pass rate metric cannot name the rows to quarantine.
  4. Files already in S3 go to a batch transcription job.
  5. Converse gives one message shape, while InvokeModel follows the body of each model.
  6. Skip NAT for Bedrock or S3 when an endpoint exists.

Flash questions

  • Q: Which Glue Data Quality entry point gives rule suggestions for a cataloged table? A: The Data Catalog entry point, since the ETL entry point offers no recommendations.
  • Q: Which Glue Data Quality entry point names the failed rows for quarantine? A: The ETL entry point, which can identify the records that failed a check.
  • Q: When does a PDF need the foundation model parser instead of Bedrock Data Automation? A: When the extraction needs a custom instruction, because that parser accepts a prompt.
  • Q: Why does a gateway endpoint for S3 not serve an on-premises caller? A: It serves only callers inside the VPC, so the on-premises path needs an interface endpoint.
  • Q: Which endpoint style suits a payload up to 1 GB when no caller waits? A: Asynchronous inference, which reads the payload from S3 and writes the result there.
  • Q: Why is a Lambda validator the wrong first choice for a rule DQDL can express? A: It recreates the scoring and result storage that Glue Data Quality already provides.
  • Q: What does a Lambda function in a VPC need before it can call an external API? A: A route to the internet through a NAT gateway, since the call otherwise times out.
  • Q: When is InvokeModel the right operation instead of Converse? A: When the required field exists only in the body format of one model.
