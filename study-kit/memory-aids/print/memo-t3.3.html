Domain 3, weight 20 percent. Read this sheet, then answer the flash questions aloud.

Etch lines

  1. A runtime guardrail acts on content, while records keep evidence after the call.
  2. CloudTrail records who called an API, but never the prompt body.
  3. A metric counts events and cannot name a user.
  4. A model card documents a release and does not block it.
  5. Clarify tracks bias against a baseline range across scheduled windows.
  6. Lineage connects a dataset to the endpoint through each step.

Flash questions

  • Q: Which record keeps the exact request and response bodies of a model call? A: Model invocation logging, sent to CloudWatch Logs or S3.
  • Q: What does a CloudTrail record hold for a Bedrock runtime call, and what is missing? A: The caller, the time, and request parameters such as the model ID. The prompt and response bodies are missing.
  • Q: Why can a streamed call look doubled when you count every CloudTrail record? A: The stream-completion event is not an API call. Count only AwsApiCall events.
  • Q: Which identifier names a stable source for each chunk in a knowledge base? A: The Glue catalog table identifier. The S3 version ID names the revision.
  • Q: Which identifier is absent for files stored before versioning was enabled? A: The version ID, since older objects carry the null value.
  • Q: Which SageMaker record documents the risk rating and intended use of a model? A: A model card. It documents a release but does not stop one.
  • Q: Which namespace holds guardrail metrics, and which metric counts interventions? A: AWS/Bedrock/Guardrails, with InvocationsIntervened as the key metric.
  • Q: Does the sensitive information filter read personal data inside tool call arguments? A: No. It reads prompts and responses, not tool use fields.
